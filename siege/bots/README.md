# siege/bots — 봇 검증 (v5)

sim을 헤드리스로 구동해 **"이 판이 게임으로 성립하는가"를 자동으로 판정**한다.
프로젝트 논지("생성이 아니라 보증")가 코드로 성립하는 지점.

```bash
pnpm verify                 # 후보 시드 전량 검증 → siege/reports/latest.{md,json}
pnpm verify --seeds 1,2,3   # 시드 지정
pnpm test                   # 봇 러너의 결정론·리플레이 일치 단언 포함
```

## 왜 이게 보증인가

- 봇이 sim에 넣는 입력은 플레이어가 넣는 입력과 **같은 타입**(`SiegeInput`)이다.
  봇 전용 뒷문이 없으므로 "봇이 검증한 판 = 플레이어가 하는 판"이 성립한다.
- 봇이 남긴 커맨드 시퀀스가 곧 **리플레이 포맷**이다. `replay()`가 같은 결과를 재현하는지
  매 검증마다 확인하고, 어긋나면 그 시드는 반려된다 — 재현 불가능한 검증은 주장일 뿐이다.
- 반려 사유는 리포트에 전량 남는다(제출물 4 「AI 활용 기술 문서」의 원재료).

## 구성

| 파일 | 역할 |
|---|---|
| `policy.ts` | 봇 3등급 — `afk`(무개입) / `greedy`(적극 플레이) / `random`(대충 조작) |
| `runner.ts` | `playout()` 판 전체 주행 + 커맨드 기록, `replay()` 재현 확인 |
| `verify.ts` | 판정 기준(`CRITERIA_V0`) + 시드별 판정 + 리포트 생성 + CLI |

등급을 셋 두는 이유: 하나로는 성립을 말할 수 없다.
무개입은 **기본 배치가 성립하는지**, 적극 플레이는 **개입이 보상되는지**,
무작위 조작은 **대충 만져도 무너지지 않는지**를 각각 잰다.

## 주의 — 틱은 고유 키가 아니다

sim은 침공 개시 시 `state.tick`을 0으로 되돌린다(침공 타임라인 기준으로 다시 셈).
그래서 커맨드는 **스텝 번호**로 키를 잡는다. 틱으로 잡으면 준비 단계의 커맨드가
침공 첫 틱 커맨드에 덮여 리플레이가 통째로 어긋난다 (2026-08-01에 실제로 겪은 버그,
`siege/test/bots.test.ts`에 회귀 테스트로 고정).
