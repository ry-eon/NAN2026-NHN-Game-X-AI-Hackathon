## 이 프로젝트의 논지 — 생성이 아니라 보증

AI가 게임을 만들었다는 사실은 흔한 주장이 된다. 여기서 제출하는 것은 그 주장이 아니라,
**만든 것이 게임으로 성립함을 시스템이 증명한 기록**이다.

결정론 시뮬레이션 위에서 **봇 4등급이 판을 직접 플레이해 판정**하고, 통과한 것만 출고한다.
봇이 넣는 입력은 플레이어가 넣는 입력과 **완전히 같은 타입**이라 뒷문이 없다 —
그래서 "봇이 검증한 판 = 플레이어가 하는 판"이 성립한다.

판정 기준은 코드에 박혀 있고(`siege/bots/verify.ts`), 그 자체가 게임 설계 주장이다:

| 봇 | 무엇을 하나 | 답하는 질문 |
|---|---|---|
| `afk` | 정말 아무것도 안 한다 | 배치가 게임에 의미 있는가 (**져야** 통과) |
| `deploy` | 표준 장착만 하고 손 뗀다 | 배치만으로 판이 성립하는가 |
| `greedy` | 겨누고, 옮기고, 스킬을 쓴다 | 개입이 **보상되는가** |
| `random` | 장착 후 엉뚱하게 만진다 | 대충 조작해도 안 무너지는가 |

현재 **시드 6종 전부 통과**. 반려 사유와 실패 데이터는 그대로 공개한다 —
그것이 검증기가 진짜라는 유일한 증거다. → [봇 검증 리포트](siege/reports/latest.md)

## 게임의 한 가지 아이디어

타워 디펜스는 보통 "적이 오는 길목에 무엇을 놓을까"를 묻는다.
이 게임은 반대로 묻는다 — **"적을 어디로 오게 만들까."**

괴수는 성벽 위 화력이 두꺼운 구간을 피해 **빈 곳으로 흐른다.** 그래서 플레이어는 대포를
한쪽으로 몰아 겨누고 반대편을 **일부러 비운다.** 비워둔 그곳이 킬존이다.

시작할 때 **대포는 비어 있다.** 수비병을 병기로 보내 장착해야 불을 뿜고, 빼면 침묵한다.
**아무것도 하지 않으면 성은 반드시 무너진다** — 배치가 이 게임의 첫 수다.

## 구조

```
siege/sim/      순수 TypeScript 결정론 시뮬레이션 — three.js·DOM을 모른다
                고정 30Hz 틱, 시드 RNG만 사용 (Math.random 금지)
siege/bots/     봇 정책 · 러너 · 판정 기준
siege/test/     결정론·리플레이·규칙 단언 (vitest)
client/src3d/   Three.js 렌더러 — sim을 구독만 한다. 게임 로직 없음
docs/           기획·설계·디렉팅 로그 (제출 문서 원고 포함)
```

렌더와 sim이 어긋나면 위 보증이 즉시 깨지므로, 성 치수·충돌·높이는 sim의 `CASTLE` 상수
하나에서만 나온다.

> `core/ bots/ pipeline/ client/src/`는 **v1~v4 2D 시절의 레거시**다(미사용).
> 전체 이력은 `legacy-2d` 브랜치에 보존돼 있다.

## 로컬 실행

```bash
pnpm install
pnpm dev        # http://localhost:5173
pnpm test       # sim 결정론·규칙·봇 하네스 단언
pnpm verify     # 봇 4등급 × 시드 6종 헤드리스 판정 → siege/reports/
pnpm build      # 타입체크 + 프로덕션 빌드 (dist/)
```

`main`에 push하면 GitHub Actions가 테스트 → 빌드 → GitHub Pages 배포를 자동으로 수행한다.
**테스트가 실패하면 배포되지 않는다.**
