## 주요 지시/프롬프트 (기술 문서 발췌용)

### 1. 선택지 자체를 반려당함 — 질문의 고도를 올린 사례
- 맥락: 4-1 궁수 역할을 묻기 위해 "관통 / 연사↑ / 상성 / 폐지" 4지선다를 제시
- 지시: **"선택지 자체가 마음에 안 든다"**
- 결과: **반려**. 네 선택지가 전부 "스탯 축 하나 고르기"였다 — 그건 밸런스 조정이지 기획이 아니다.
  한 단계 위에서 "이 게임에서 플레이어가 내리는 재미있는 결정이 무엇이어야 하나"로 다시 물었고,
  거기서 **배치 판단**이라는 축이 나왔다. 병종 구성·궁수 역할·괴수 특징이 전부 그 밑으로 따라왔다.
  → 교훈: 하위 항목을 못 정하는 건 상위 축이 안 정해졌기 때문일 때가 많다.

### 2. 사실 오류를 코드로 잡아낸 사례
- 맥락: 사용자가 "4면은 어려울 것 같고 세미 3면 정도 어떨까"라고 답함
- 지시(내 확인): 침공 방향 코드를 실제로 열어봄
- 결과: **내 설명이 틀렸음을 발견**. 괴수는 4면이 아니라 **동쪽 1면**에서만 왔다
  (`world.ts` 스폰이 `x: FIELD.maxX - 1` 고정, z만 산개). 4면 개방은 *플레이어 보도* 이야기였다.
  즉 "세미 3면"은 사용자가 생각한 축소가 아니라 **확장**이었다. 그 사실을 알린 뒤 다시 물어
  「정면 전폭 + 모서리 회절」로 확정.
  → 교훈: 기획 질문을 던지기 전에 현재 코드가 실제로 뭘 하는지 확인할 것. 잘못된 전제 위의 선택은 되돌려야 한다.

### 3. 확정 대신 의견을 요구받은 사례
- 맥락: 배치 반응 규칙에서 "화망으로 빈 곳 유도"와 "구조물로 킬존 유도" 둘 다 원한다는 답
- 지시: **"둘 다 하고 싶은데 어떻게 해야 할까? 확정 말고 의견부터"**
- 결과: 채택. 둘이 같은 메커니즘(경로 비용)의 부드러운/단단한 버전임을 정리하고,
  "비어 있으면서 동시에 치명적일 수 없다"는 모순을 지적한 뒤 **가시성 + 지연** 두 규칙으로 푸는 안을 제시.
  구조물은 컨셉(농성 vs 야전 요새화)과 비용을 이유로 폴백 권고 → 사용자가 1+2 채택.

### 4. 괴물 디자인 — 순서를 되물은 사례
- 지시: "이건 괴물 디자인을 확정하고 해야 하지 않나?"
- 결과: 확인해보니 **디자인은 이미 07-30에 확정돼 있었다**(`models.ts:706` `makeMonster`, 3종 골격·보행·무기 상이).
  순서가 막힌 게 아니라 실루엣이 이미 행동을 지시하고 있었다는 점을 표로 제시.
  다만 사용자는 **디자인 수정·추가**를 선택 → 조형 개선(스케일·실루엣 분화·질감) + 보스 1기.
  "반드시 기괴할 필요는 없다"며 기괴함 축은 **명시적 기각**, 대신 「언데드 군세」 컨셉 확정.

### 5. 일정 오해를 지적당한 사례
- 맥락: 내가 "개발 가능일은 8/4~8/6 사흘"이라며 규모를 경고
- 지시: **"마감일은 10일인데 어디서부터 오해가 생긴 걸까?"**
- 결과: **내 오류**. `docs/04-milestones.md`의 날짜 배분(8/7~8/9 제출)을 마감처럼 취급했는데,
  그 배분은 "기획이 8/3에 끝난다"는 전제로 짠 것이었다. 전제가 깨졌으면 배분을 다시 짜야 한다.
  제출 작업 실측 재산정(public 전환 1h + 영상 반나절 + PDF 1일 ≈ 1.5~2일) → **개발 가능일 나흘**로 정정.

## §4-3 재배치 비용 룰 — 사용자가 제3의 설계를 냄

- 지시: **"대포 자체는 고정한다, 다만 쏘는 위치를 지정한다. 날아가는 경로를 보이게 해
  거리에 따라 날아가는 시간을 별도로 한다. 병사 일부는 몬스터가 침범했을 때 백병전 인력으로
  변동할 수 있다"**
- 결과: 내 선택지(4지선다) 어느 것도 아닌 새 설계. 채택.
  무작위 반려가 **구조적으로 사라진다** — 대포를 못 옮기니 잘못된 명령이 대포를 침묵시킬 수 없다.

### 내가 지적한 충돌과 해소
대포가 고정이면 구간별 위협이 영원히 균일해서 **플레이어가 화망을 못 몬다** = 유도가 작동은 하되
손잡이가 사라진다. 제안: **위협을 위치가 아니라 조준에서 계산한다.** 사용자 승인
("1 + 대포/발리스타 개수는 늘린다").

### 구현 중 겪은 반전 둘
1. **기본 조준을 자기 정면으로 뒀더니 무개입 0/6.** 조준이 기본값부터 제약이 돼서
   손대지 않은 판이 성립하지 않았다 → 초기값을 자동 조준(null)로. 조준은 선택적 개선이어야 한다.
2. **증원이 오히려 판정을 떨어뜨렸다** (5/6 → 4/6, 대역 0~1/6). 원인은 구조적 절벽:
   성벽 HP가 공유 풀이라 벽에 붙은 수가 임계를 넘으면 초당 800+ 피해로 즉사한다
   (51기 4/6 → 61기 0/6). **개체당 벽 피해를 65% 낮추고 수를 늘려** 절벽을 완만하게 만들자
   증원과 통과를 동시에 얻었다.

### 봇도 같이 고쳤다 (검증이 시늉이 되지 않게)
손잡이가 이동에서 조준으로 바뀌었으므로 봇도 바뀌어야 한다. 특히 **random**:
이동 명령만 무작위로 넣으면 고정 병기가 전부 무시해서 사실상 무개입과 같아진다 —
그 봇은 통과하지만 검증은 의미를 잃는다. "대충 만진다"의 실체를 **엉뚱한 조준**으로 바꿨다.

## 보스 네크로맨서 + 부활 (같은 날 이어서)

- 지시: **"더 먼저 해야 하는 걸 진행. 기존 순서를 억지로 지키려고 할 필요는 없어"**
- 판단: 실루엣 분화·투사체는 둘 다 밸런스를 다시 흔든다. 그보다 먼저,
  **오늘 세 커밋이 핵심 조작을 바꿨는데 아무도 실제로 플레이해본 적이 없다**는 게 최대 위험이었다.
  → 실기기 스모크 테스트 먼저 → 결함 3건 발견(별도 커밋) → 그다음 보스.

### 봇이 설계를 교정한 사례
처음 수치(HP 3200·쿨 7초·3기·55%·standoff 13)로는 **무개입이 1/6**. 원인은 자동 조준이
