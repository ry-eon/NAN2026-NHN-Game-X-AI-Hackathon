## 주요 지시/프롬프트 (기술 문서 발췌용)
- 맥락: 리포 push 완료(private, Pages는 public 전환 시 자동 재개) 후 "다음 작업 진행" 지시.
- 지시: 다음 작업 위임 → 에이전트 판단으로 봇 등급 완성을 선택.
  근거: 등급 간 성과 격차가 파이프라인 판정의 핵심 입력이라 생성기보다 선행돼야 함.
- 결과: 채택. Random(하한)·Planner(상한) + evaluateBots 집계기, 테스트 17종 전부 통과.

## 결정 사항
- **Random 봇**: 1초마다 50% 확률로 무작위 유닛·무작위 유효 타일 배치. core 시드 RNG만
  사용 — 같은 시드 = 같은 플레이 (평가 재현성).
- **Planner 봇**: 킬존 계획(원거리 커버리지 최대 진입로 셀 = 초크포인트), 최적 블로커
  대기(코스트 저축 — Greedy와 갈라지는 지점), 저지/DPS 부족 판단 배치, 누수 긴급 대응.
  상수(DPS 지평 12s 등)는 전부 [초안].
- **evaluateBots**: 봇×N회 → 클리어율, 평균 성벽 잔여율, 평균 클리어 시간 집계.
  판정 임계값은 넣지 않음 — 난이도 지표 확정은 [미결]이므로 사용자 논의 후.

## 측정 결과 (stage-001, 봇별 10회)
| 봇 | 클리어율 | 평균 성벽 잔여 | 평균 시간 | 배치 수 |
|---|---|---|---|---|
| Planner | 100% | 100% | 47.3s | 4 |
| Greedy | 100% | 100% | 47.8s | 6 |
| Random | 100% | 97.6% | 47.2s | 6 |
- **Random까지 100% 클리어 = stage-001은 등급 변별력 0인 하급 스테이지.**
  어제 사용자의 "수준이 너무 낮다" 지적이 지표로 정량 확인됨. 직선 외길 + 넉넉한
  코스트 구조라 아무렇게나 놓아도 막힌다.

## 추가 세션 (같은 날): stage-002 "갈라진 진격로" — 등급 변별력 확보
- 지시: "1번 스테이지 002부터 진행해줘"
- 설계: 이중 레인(A 꺾임/B 직선) + 성벽 위 배치 3칸 제한 + 타이트 경제(초기 10, 0.8/s)
- **밸런싱 8회 반복** (전 과정 프로브 계측 기반, 기술 문서용 핵심 서사):
  1. 초판: 전 등급 100% 클리어 — 압박 부족
  2. Planner가 레인 B를 53s까지 방치 → 저지 부족 판정을 전역→경로별로 수정
  3. Greedy가 아처 6기 도배로 무손상 클리어 발견 → 성벽 위 3칸 제한 (맵 수정)
  4. 동시 페어 투입 → Planner 저축 규칙이 아처 구매를 고사시켜 전패 →
     "제때 모을 수 있을 때만 저축" + 부족 판정에 ETA 10s 창 도입
  5. 여전히 Planner 전패: 성벽 캠핑 적을 원거리 없이 못 죽임 →
     오프너(원거리 0기면 최우선)·캠퍼 청소 규칙 추가
  6. 오프너가 커버 얇은 레인을 놓침 → "최약 레인 커버 최대화" 균형 오프너로 교체
  7. 적 스탯 상향(보병 480/속행 190/중장 1250) — 아처 3방 컷이 원거리 스팸의 근원
     → W1은 완만하게 되돌려 난이도 램프 형성
  8. 조합은 갈렸지만 Planner의 레인 B 근접이 0.8s 늦어 4클럼프 누수 →
     **스폰 테이블 사전 계획(predictClumps)**: 동시 도착 무리를 예측해 도착 전에
     해당 레인 저지 capacity 확보. Planner의 정의("계획")를 실제로 구현한 조각.
- **최종 실측 (봇별 10회)**: Planner 클리어 100%·성벽 잔여 55% / Greedy 100%·30% /
  Random 10%·1% — 3단 분리 달성, 테스트로 고정 (bots/test/stage-002.test.ts)
- client: 스테이지 선택 버튼 + 맵 크기 가변 타일. 헤드리스 스크린샷으로 확인.
- 배운 것: 봇 등급이 맵 설계 결함(아처 스팸 지배 전략)을 자동으로 찾아낸다 —
  "봇 = 스테이지 검증기" 논지가 밸런싱 도구로도 성립함을 확인.

## 추가 세션 (같은 날): 파이프라인 폐루프 — W2 완료 기준 조기 달성
- 지시: "다음 진행. 문서 작업도 병행 필수로 작성"
- 구현: `pnpm pipeline` 한 번으로 [1]생성→[2]정적검증→[3]봇시뮬→[4]지표→[5]판정→[6]출고.
  - 생성: 절차적(시드 변형 — 크기/레인 1-2/꺾임/성벽 슬롯 2-4/경제/3웨이브 램프).
    core와 같은 mulberry32 → 같은 시드 = 같은 스테이지.
  - 판정: CRITERIA_V0 [초안] — UNSOLVABLE(Planner<100%) / TRIVIAL(Random≥50%) /
    DEGENERATE(유닛<2종) / OFF_CURVE(--tier 불일치) / 티어 EASY·NORMAL·HARD.
  - 출고: pipeline/accepted/*.json(진실 원천) → generated.ts 코드젠 → STAGES 자동 포함.

  - 리포트: 실행마다 reports/에 JSON+MD, 반려 사유 전량 기록 (기술 문서 원자료).
- 실측: 12후보 → 출고 8 / 반려 4 (TRIVIAL 3, UNSOLVABLE 1). 1차 생성기는 TRIVIAL 4/6으로
  수율 17% → 웨이브 압박 상향 후 67%. 출고분 gen-0100이 브라우저에서 플레이되는 것까지
  스크린샷 확인 — "생성 → 검증 → 출고 → 플레이" 폐루프 완성.
- 문서 병행: docs/05-pipeline.md에 구현 현황·CRITERIA_V0 제안표·실측·논의 안건 3건 추가,

## 추가 세션 (같은 날): 유닛 6종·적 4종 완성 — W2 콘텐츠 항목
- 지시: "다음 진행해줘" (문서 병행 유지)
- core 신규 메커니즘 4종: 광역 피해(술사, aoeRadius) / 아군 치유(의무병, heals) /
  감속 오라(감속사, aura) / 원거리 성벽 포격(공성차, wallAttackRange — 경로 끝
  2.5타일 앞 정지). 마이크로 스테이지 테스트 5종으로 각각 검증.
- **공성차가 드러낸 설계 구멍**: 포격 지점이 원거리 사거리 밖이면 처치 수단이 게임에
  존재하지 않음(근접은 저지된 적만 공격 가능했음) → core에 "근접은 자기 칸(0.7타일)의
  적을 저지 없이 공격 가능" 규칙 추가 + Planner에 "원거리 불가 시 그 칸에 근접 배치"
  대응. 신규 콘텐츠가 시스템 결함을 드러내고 파이프라인(UNSOLVABLE 급증)이 그걸
  정량으로 보여준 사례.
- **봇 구매 풀에서 유틸리티(치유·오라) 제외**: Greedy가 8코스트 감속사를 초크마다
  사버려 stage-002 전패 → "봇은 저지·화력 유닛만 산다"로 정리. 유틸 유닛 운용
  독트린(힐러 타이밍, 감속 위치)은 W3 과제로 명시. 난이도 신호의 로스터 안정성 확보.
- 힐러 테스트 1차 실패(자체): 스폰 없는 마이크로 스테이지가 1틱 만에 승리 처리 →
  먼 미래 스폰으로 게임 유지. 테스트 인프라의 함정 기록.
- 생성기: 공성차 35% 투입 + 물량을 경제(재생률)에 연동 — 저경제 맵의 UNSOLVABLE
  낭비 감소 (시드 300: 6/12, 시드 500: 10/12 출고).
- 테스트 30종 통과. 카드 UI 6종 콤팩트 재배치(96px, 1~6키).
