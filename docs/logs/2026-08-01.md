# (같은 날 3차 세션) 톤 그레이딩 — 그래픽 로드맵 종료

## 오늘의 목표
- 로드맵 마지막 항목 **톤 그레이딩** (사용자 "우선 다음 작업 진행")

## 구현
- **패스를 늘리지 않는 것이 핵심 제약**: 전화면 패스 하나가 곧 프레임 비용이라(SSAO를 뺀 이유)
  기존 비네트 ShaderPass를 그레이딩 패스로 확장했다. 추가 비용은 픽셀당 산술 몇 줄뿐.
- 이 패스는 OutputPass(ACES 톤매핑) **이전**, 즉 선형 HDR 공간이다. 그래서
  (1) 스플릿 톤 — 밝기를 `l/(l+0.35)`로 정규화해 그림자엔 하늘빛 `lift`, 하이라이트엔 햇살 `gain`,
  (2) 대비 — 중간 회색 0.18 피벗 기준 pow, (3) 채도 — 루마 기준 lerp, (4) 비네트 순으로 건다.
- 의도: 돌·금속의 명암이 색보다 먼저 읽히게(채도 -12%) + 그림자/햇빛의 색온도 분리로 입체감.
  사용자 기준 "다크소울 = 렌더링 퀄리티"에 대응하는 마감 작업.
- `__siege.grade` 개발 훅 추가 — 색감은 말로 합의가 안 되므로 빌드 없이 수치를 만지고
  스크린샷으로 A/B 할 수 있게 했다. (`grade.u.saturation.value`, `grade.exposure(v)`)

## 반려·재시도 기록
- 강도 A/B를 실 GPU 스크린샷으로 3단 비교: 약(1.08/0.92) → 눈에 띄지 않음,
  강(1.16/0.85) → 안뜰이 푸르게 잠겨 **"밤이 안 보인다"는 기존 반려 사유**에 가까워짐.
  → 중간값(대비 1.12 / 채도 0.88 / lift 0.92,0.965,1.10 / gain 1.10,1.0,0.87) 채택.
  가독성이 색감보다 우선이라는 기존 결정을 따랐다.

## 검증
- `pnpm test` 70/70, typecheck·build 통과. sim 무변경.
- 그레이딩 off/약/강/중간을 같은 시점에서 촬영해 비교 — 채택값에서 햇빛 받는 보도는
  따뜻하게, 그늘진 안뜰은 차갑게 갈라지고 인물 실루엣은 그대로 읽힌다.
