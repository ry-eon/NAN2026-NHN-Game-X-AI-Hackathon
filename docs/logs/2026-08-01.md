# (같은 날 3차 세션) 톤 그레이딩 — 그래픽 로드맵 종료

## 오늘의 목표
- 로드맵 마지막 항목 **톤 그레이딩** (사용자 "우선 다음 작업 진행")

## 구현
- **패스를 늘리지 않는 것이 핵심 제약**: 전화면 패스 하나가 곧 프레임 비용이라(SSAO를 뺀 이유)
  기존 비네트 ShaderPass를 그레이딩 패스로 확장했다. 추가 비용은 픽셀당 산술 몇 줄뿐.
- 이 패스는 OutputPass(ACES 톤매핑) **이전**, 즉 선형 HDR 공간이다. 그래서
  (1) 스플릿 톤 — 밝기를 `l/(l+0.35)`로 정규화해 그림자엔 하늘빛 `lift`, 하이라이트엔 햇살 `gain`,
  (2) 대비 — 중간 회색 0.18 피벗 기준 pow, (3) 채도 — 루마 기준 lerp, (4) 비네트 순으로 건다.
- 의도: 돌·금속의 명암이 색보다 먼저 읽히게(채도 -12%) + 그림자/햇빛의 색온도 분리로 입체감.
  사용자 기준 "다크소울 = 렌더링 퀄리티"에 대응하는 마감 작업.
- `__siege.grade` 개발 훅 추가 — 색감은 말로 합의가 안 되므로 빌드 없이 수치를 만지고
  스크린샷으로 A/B 할 수 있게 했다. (`grade.u.saturation.value`, `grade.exposure(v)`)

## 반려·재시도 기록
- 강도 A/B를 실 GPU 스크린샷으로 3단 비교: 약(1.08/0.92) → 눈에 띄지 않음,
  강(1.16/0.85) → 안뜰이 푸르게 잠겨 **"밤이 안 보인다"는 기존 반려 사유**에 가까워짐.
  → 중간값(대비 1.12 / 채도 0.88 / lift 0.92,0.965,1.10 / gain 1.10,1.0,0.87) 채택.
  가독성이 색감보다 우선이라는 기존 결정을 따랐다.

## 검증
- `pnpm test` 70/70, typecheck·build 통과. sim 무변경.
- 그레이딩 off/약/강/중간을 같은 시점에서 촬영해 비교 — 채택값에서 햇빛 받는 보도는
  따뜻하게, 그늘진 안뜰은 차갑게 갈라지고 인물 실루엣은 그대로 읽힌다.

## 지시

## 왜 결함이었나
- **재시작**: 키 핸들러가 Space/ESC/E/T/숫자뿐이었다. 승패 후 문구만 바뀌고 sim은 멈추는데

  느린 회선에선 검은 들판·민무늬 성벽이 그대로 보인다. 실제로 4차 세션에서 dev 서버가 죽었을 때

## 구현
- **로딩 화면**: `THREE.DefaultLoadingManager`에 콜백을 걸어 진행률 바 + `n / total` 표시.
  로더 등록보다 먼저 걸려야 해서 에셋 호출부(loadSky/buildCastle) **위에** 뒀다.
  안전장치 2개 — 에셋 로드가 아예 시작되지 않으면(캐시 전량 적중) 1.5초 뒤 닫고,
  어떤 이유로든 onLoad가 안 뜨면 20초 뒤 닫는다. `onError`는 경고만 남기고 계속(절차 생성이 본체라
  에셋 하나 실패로 게임이 성립 못 하는 구조가 아니다).
- **재시작**: `resetGame()` — sim은 `createSiege(SEED)`로 통째로 새로 만들면 끝(결정론이라
  이전 판의 흔적이 남을 수 없다). 렌더 쪽은 판에 종속된 것만 회수한다:
  괴수/유닛 비주얼·시신·투사체·섬광·충격파·화염·임시 광원·영웅 카드·선택/컨트롤 그룹·
  입력 래치·trauma. **배경·성채·입자 풀은 판과 무관하므로 그대로 재사용**한다(다시 짓지 않는다).

  검증 훅이 옛 스냅샷을 붙들지 않게 했다.
- **종료 카드**: 승/패 문구 + 버틴 시간·잔여 성벽·생존 병력 요약 + "다시 하기 (R)" 버튼.

# (같은 날 7차 세션) 봇 검증 재구축 — 논지 복원

## 지시

## 무엇을 만들었나 (`siege/bots/`)
- `policy.ts` — 봇 3등급. 하나로는 "성립한다"를 말할 수 없어서 셋을 둔다:
  **afk**(무개입 = 기본 배치가 성립하는가) / **greedy**(적극 플레이 = 개입이 보상되는가) /
  **random**(대충 조작 = 심사자가 만져도 무너지지 않는가).
- `runner.ts` — `playout()`이 판을 끝까지 돌리며 **커맨드 시퀀스**를 남기고,
  `replay()`가 그 시퀀스만으로 같은 판을 재현하는지 확인한다.
- `verify.ts` — 판정 기준 `CRITERIA_V0` + 시드별 판정 + 리포트(`siege/reports/latest.{md,json}`) + CLI.
  출고 시드가 반려되면 종료코드 1 (CI에 걸 수 있다).
- `siege/test/bots.test.ts` — 결정론·리플레이 일치·출고 시드 현황을 단언(6건 추가, 총 76).

**보증이 성립하는 근거**: 봇이 넣는 입력은 플레이어가 넣는 입력과 같은 타입(`SiegeInput`)이고
봇 전용 뒷문이 없다. 그래서 "봇이 검증한 판 = 플레이어가 하는 판"이 말이 된다.

## 봇이 즉시 잡아낸 것 3건

1. **리플레이 포맷 버그(내 도구 버그)** — 첫 검증에서 모든 시드가 "리플레이 불일치"로 반려됐다.
   원인은 sim이 침공 개시 시 `state.tick = 0`으로 되돌린다는 사실(침공 타임라인 기준으로 다시 셈).
   **틱은 판 전체에서 고유 키가 아니었다** — 준비 단계의 커맨드가 침공 첫 틱 커맨드에 덮여
   `startAssault`가 통째로 사라졌고, 재생된 판은 영원히 준비 단계에 머물렀다.
   → 커맨드 키를 **스텝 번호**로 바꾸고 회귀 테스트로 고정. 08-status의 "커맨드형 입력 = 그대로
   리플레이 포맷"이라는 서술이 미묘하게 틀렸던 셈이고, 봇을 붙이지 않았으면 못 찾았을 종류다.
2. **재배치는 화력을 포기하는 거래다** — 2초마다 재배치하는 1차 greedy가 무개입보다 크게 졌다.
   sim 규칙상 유닛은 **정지 시에만 사격**하므로 이동 = 사격 중단이다. 8초에 한 번, 정말 멀리
   떨어진 궁수 절반만 보내도록 고치자 greedy가 무개입을 앞질렀다(성벽 630 > 500).

3. **밸런스 결함(게임 문제)** — 아래.

# (같은 날 8차 세션) 로스터·배치를 데이터로 — 기획 시험 도구

## 지시 / 판단

  **밸런스 패치는 기획 이후에 해야 할 듯?** 먼저 개발로 할 게 있어?"
- 동의. 로스터가 안 정해진 상태의 밸런스 숫자는 기획 확정 후 전부 버려진다.
  대신 **기획을 빠르게 시험할 도구**는 지금 만들어도 그대로 쓰인다 → 사용자가 A안 선택.

## 무엇을 했나
- **`Loadout` 도입** (`siege/sim/world.ts`) — 유닛 정의·몬스터 정의·초기 배치·웨이브 구성·성벽 HP를
  sim 로직에서 떼어낸 데이터 묶음. `createSiege(seed, loadout?)`로 주입한다.
  sim 내부는 이제 모듈 상수가 아니라 **`state.kinds`**를 본다 — 그래야 한 프로세스에서
  서로 다른 편성을 동시에 돌려 비교할 수 있다(봇 스윕이 그렇게 돈다).
  렌더러도 `state.kinds` / `state.wallHpMax`를 본다.
- **웨이브를 선언형으로** — `WaveDef {wave, kind, count, at, every, z, altKind}`.
  하드코딩 루프 3개가 데이터 5줄이 됐다.
- **프리셋** (`siege/sim/loadouts.ts`) — default / cannon-heavy(대포 4) / cannon-only(대포 6) /
  archer-line(궁수 8) / thick-wall(성벽 3000).
- **`pnpm verify --compare`** — 프리셋 전부를 같은 시드·같은 봇으로 돌려 표로 뽑는다.
  `--loadout <name>`으로 특정 편성만 판정할 수도 있다.
- 테스트 5건 추가(총 81) — 기본 로드아웃이 출고 판 그대로인지, 주입이 실제로 먹는지,
  프리셋 무결성(영웅 1기·정의 없는 병종 금지), 웨이브 표 생성.

## 봇이 답한 기획 질문 (`siege/reports/loadouts.md`)

| 편성 | 구성 | afk 승률 | 평균 잔존 | greedy 승률 | random |
|---|---|---|---|---|---|
| default (출고) | 궁수 6 · 대포 2 · 발리스타 2 | 5/6 | 343 | 2/6 | 0/6 |
| cannon-heavy | 궁수 4 · **대포 4** · 발리스타 2 | **6/6** | **945** | 5/6 | 0/6 |
| cannon-only | **대포 6** · 발리스타 2 | 6/6 | 1010 | 6/6 | 0/6 |
| archer-line | **궁수 8** · 대포 2 | **0/6** | 0 | 0/6 | 0/6 |
| thick-wall | 기본 + 성벽 3000 | 6/6 | 1330 | 5/6 | 0/6 |

1. **사용자의 직감이 맞았다** — 대포가 적었다. 2→4로 늘리면 무개입 승률 5/6→6/6,
   평균 잔존 343→945.
2. **화력 축이 대포에 쏠려 있다** — 궁수 8 편성은 전 시드 전멸(0/6). 지금 궁수는 사실상
   기여를 못 하고 대포·발리스타가 판을 캐리한다. 병종 밸런스가 무너져 있다는 뜻이고,
   기획에서 궁수의 역할(대공? 대군중? 사거리?)을 다시 정할 근거가 된다.
3. **random은 어떤 편성에서도 0/6** — 편성으로는 해결되지 않는다. 재배치 비용(이동 중 사격 불가)이
