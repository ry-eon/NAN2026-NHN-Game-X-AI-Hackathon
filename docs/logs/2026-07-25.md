## 성문 위 보도 연속화 (2층 지형) + 시야 가림 원통 제거

**사용자 피드백**: "성벽 중간이 통과가 안되고, 성벽에 그 원통 구조물이 시야를 가릴 거 같아서 빼는 게 나을지도?"

### 문제
- 기존 지형은 `heightAt(x,z) → 단일 높이`라서 성문 구간(|z| < gateHalf)은 터널(0)로만 취급 → 보도가 성문 위에서 끊김.
- 성문 위를 다리로 만들려면 같은 (x,z)에 **두 높이가 공존**해야 함: 위로는 보도(11), 아래로는 터널(0).

### 해결: 2층 지형 시스템 (sim 리팩터)
- `heightLevels(x,z): number[]` — 좌표별 후보 높이 목록. 성문 스트립은 `[wallH, 0]` 반환.
- `stepHeight(fromH, toX, toZ)` — 현재 높이에서 연속(Δ≤1.5)으로 이어지는 층만 선택. 절벽 낙하 차단.
- `LordState.h` 추가 — 성주의 현재 층을 시뮬레이션 상태로 추적.
- `findPath`를 레벨 확장 BFS로 — 노드 = 셀×2+층, 클릭한 면의 높이(`moveTo.h`)를 힌트로 받아 다리 위/터널 아래를 구분해 목표.
- 클라이언트: 구조물 상면 클릭 시 `h: hit.point.y` 전달, 렌더 높이는 `lord.h` 보간(더 이상 heightAt 조회 없음).

### 검증 (렌더 없는 sim 단독 테스트)
- 보도 남→북 성문 위 직행: **OK 22칸** (우회 아님 — 끊겼다면 실패 또는 60칸+ 우회)
- 지상 성문 터널 통과: OK 22칸 / 계단 등벽: OK 23칸
- 성문 위 좌표의 층 후보: `[11, 0]` 확인

### 원통 망루
- 동쪽(전면) 망루 2기 완전 제거 — 보도에서 시야 가림 원인. sim 콜라이더와 렌더 메시 동시 제거(단일 원천 원칙).
- 서쪽(후방) 2기는 실루엣용으로 유지 — 시야에 걸리지 않는 위치.

### 교훈
- "같은 좌표에 두 높이"는 단일 높이맵으로는 표현 불가 — 처음부터 다층 지형으로 설계했어야 할 부분을 피드백 받고 리팩터. 지형 쿼리를 sim에 격리해 둔 덕에 클라이언트 수정은 3줄.

- 벽체 노치는 메웠지만 **파라펫 라인**이 모서리에서 안 만났음 — 동/서벽 파라펫은 벽 구간 끝(z=±18)에서 멈추고 북/남벽 파라펫은 바깥 립(3.45 오프셋)에 있어 사이 ~4유닛이 계단처럼 비어 보임.
- 네 모서리에 파라펫 필러 + 2.2 높이 모서리 캡 블록 추가. 확대 스크린샷으로 라인 연속 확인.
- 교훈: "벽을 연장했으니 모서리 해결"이라 판단했지만 파라펫은 별도 오브젝트라 따로 이어야 했다. 구조물 수정 시 본체·장식 레이어를 각각 점검할 것.

### 후속: 성가퀴 간격 통일 (사용자 재지적)
- 성문 좌우로 성가퀴 간격이 어긋남 — 각 벽 구간이 구간-로컬 기준으로 배치했고 성문 상부는 규격 자체가 달랐음(1.6 폭·2.1 간격 vs 2.1 폭·4.2 간격).
- 전 구간을 **월드 좌표 4.2 그리드**로 정렬: 이음새와 무관하게 -4.2, 0(성문 중앙), +4.2… 리듬 유지. 성문 상부도 동일 규격 1기로 교체.
